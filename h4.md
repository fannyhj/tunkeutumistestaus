Tämä on tehtäväraportti Tero Karvisen Tunkeutumistestaus-kurssille (ICI005AS3A-3007). Tehtävänannoissa on hyödynnetty Tero Karvisen Tunkeutumistestaus-läksysivuilla annettuja ohjeita. (Karvinen 2026)

## x) Lue/katso ja tiivistä

## [OWASP 2021: OWASP Top 10:2021](https://top10.owasp.org/2021/A01_2021-Broken_Access_Control/)

- Access Control valvoo käytäntöä siten, että käyttäjät eivät voi toimia heille annettujen käyttöoikeuksiensa ulkopuolella.
- Yleisiä access control rikkomuksia on mm.:
  - Least privilage -periaatteen rikkominen
  - Kulunvalvonnan tarkistusten ohittaminen muokkaamalla URL-osoitetta
  - Jonkun toisen tilin katselun tai muokkauksen salliminen antamalla yksilöllisen tunnisteen 
  - API:n käyttäminen silloin, kun POST-, PUT- ja DELETE-pyyntöjen pääsynhallinta puuttuu.
  - Käyttöoikeuksien korottaminen (Elevation of privilege): Käyttäjä pystyy toimimaan käyttäjänä ilman kirjautumista tai toimimaan ylläpitäjänä, vaikka hän on kirjautunut sisään tavallisena käyttäjänä.
  
(OWASP 2021)

## [PortSwigger Academy: Insecure direct object references (IDOR)](https://portswigger.net/web-security/access-control/idor)

- Insecure Direct Object Reference (IDOR) on pääsynhallinnan haavoittuvuus, joka tapahtuu, kun sovellus hyödyntää käyttäjän antamaa syötettä suoraan objektien käyttämiseen.
- Hyökkääjä pystyy tekemään horisontaalisen tai vertikaalisen käyttöoikeuksien korotuksen vaihtamalla käyttäjän sellaiseksi, jolla on enemmän oikeuksia, ja samalla ohittamalla pääsynhallinnan.
- Muita tapoja on esimerkiksi leakattujen salasanojen hyödyntäminen tai parametrien muokkaaminen sen jälkeen, kun hyökkääjä on päässyt käyttäjän tilisivulle.

(PortSwigger s.a. a)

## [PortSwigger Academy: Path traversal](https://portswigger.net/web-security/file-path-traversal)

- Path traversal, tai directory traversal, on haavoittuvuus, jolla hyökkääjä voi lukea tiedostoja palvelimelta, jolla sovellus toimii. Näitä voi olla esim: 
  - Sovelluksen lähdekoodi ja data
  - Taustajärjestelmien kirjautumistiedot ja tunnukset
  - Käyttöjärjestelmän arkaluontoiset tiedostot
- Monet sovellukset sisältävät suojauksia path traversal -hyökkäyksiä vastaan. Nämä suojaukset voidaan kuitenkin usein kiertää esim. käyttämällä absoluuttista polkua roottiin parametreillä "filename=/etc/passwd" tai "....// or ....\/".

(PortSwigger s.a. b)

## [PortSwigger Academy: Cross-site scripting](https://portswigger.net/web-security/cross-site-scripting)
- Cross-site scripting, tai XSS, on haavoittuvuus, jonka avulla hyökkääjä voi hyödyntää vuorovaikutuksia, joita käyttäjillä on haavoittuvan sovelluksen kanssa.
- Tämän avulla hyökkääjä voi kiertää same-origin policy -suojauskäytännön, jonka tarkoituksena on eristää eri verkkosivustot toisistaan.
- Nämä mahdollistavat yleensä sen, että hyökkääjä voi esiintyä uhrina, suorittaa samoja toimintoja kuin käyttäjä ja päästä käsiksi käyttäjän tietoihin.
- Jos uhrilla on sovelluksessa korkeammat käyttöoikeudet, hyökkääjä voi mahdollisesti saada täyden hallinnan sovelluksen kaikkiin toimintoihin ja tietoihin.

(PortSwigger s.a. c)

## a) Totally Legit Sertificate

Asensin ensiksi virtuaalikoneelleni ZAP:in komennolla "sudo apt install zaproxy". Latauksen jälkeen avasin ohjelman komennolla "zaproxy". Avautuneesta ohjelmasta etsin Tools → Options → Network → Server Certificates ja loin itselleni CA-sertifikaatin. CA-sertifikaatin avulla selain voi luottaa ZAP-välityspalvelimen luomiin sertifikaatteihin, jolloin ZAP pystyy sieppaamaan, purkamaan ja tarkastelemaan HTTPS-liikennettä selaimen ja kohdesivuston välillä ilman selaimen sertifikaattivaroituksia.
